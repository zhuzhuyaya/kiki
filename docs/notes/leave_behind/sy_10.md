# 常见报错速查表

> 项目开发期踩过/预防过的坑，按类别归档。遇到报错先来这里对暗号。

## 一、框架行为类

### favicon.ico 触发 ERROR 全堆栈

浏览器打开任何网站都会自动请求一次 `/favicon.ico`，工程没有静态资源能匹配，Spring 6.1+ 抛 `NoResourceFoundException`，被兜底 `Exception` handler 捞走，当成系统异常打 ERROR + 堆栈。

**修复**：高频"预期内异常"单独开 handler 压低级别：

```java
@ExceptionHandler(NoResourceFoundException.class)
public Result<Void> handleNoResource(NoResourceFoundException e) {
    log.debug("资源不存在: {}", e.getResourcePath());
    return Result.fail(404, "资源不存在");
}
```

**教训**：兜底 handler 会把 404 类也捞进来刷日志；想根治图标请求，丢个 `favicon.ico` 到 `src/main/resources/static/`。

### MP 分页静默失效（不报错但查全表）

没注册 `PaginationInnerInterceptor` 时，`selectPage` 悄悄变成查全表。**不报错的错误最致命**，所以分页插件在第一个配置类就装上。

### 401/403 掉进 500 兜底

没登录访问受保护接口，Sa-Token 抛 `NotLoginException`，不处理就变成"500 系统异常"，语义全错。要为 `NotLoginException`（401）、`NotRoleException`（403）各开 handler。

### 同名 Controller 导致启动失败（Bean 名冲突）

第 3 课"整体替换"第 1 课的 AuthController 时，只新建没删旧，一启动：

```
ConflictingBeanDefinitionException: Annotation-specified bean name 'authController'
for bean class [com.shiyi.module.auth.controller.AuthController]
conflicts with existing, non-compatible bean definition of same name and class
[com.shiyi.module.auth.AuthController]
```

**原因**：Spring 扫描 `@RestController` 时默认 Bean 名 = 类简名首字母小写，两个不同包里的同名类 → 容器里两个 `authController` → 拒绝启动。注意两个类的 URL 并不冲突（各自路径不同），**冲突发生在 Bean 名这一层**，所以编译不报错、一运行才炸。

**解法**：物理删除旧文件。读报错技巧——`of same name and class [完整类名]` 会点名打架双方，谁留谁删一目了然。

**教训**："替换类" = 新建 + 删旧，IDEA 不会替你发现跨包的同名组件类。

### 分页参数缺省导致 500（原始类型接不住 null）

访问 `/users` 没带 `?page=&size=` 时：

```
IllegalStateException: Optional long parameter 'page' is present but cannot be
translated into a null value due to being declared as a primitive type.
```

**原因**：查询参数缺席时 Spring 想绑定 null，而 `long` 原始类型天生不能为 null。

**解法**：`@RequestParam(defaultValue = "1") long page`，缺省走默认值。

参数绑定三种写法的决策梯：

| 写法 | 参数缺失时 | 适用 |
| --- | --- | --- |
| 裸 `long page` | 500（本例） | ❌ 别用 |
| `@RequestParam long page` | 400 提示缺参 | 必填参数 |
| `@RequestParam(defaultValue = "1")` | 用默认值 | 分页等有惯例默认值的参数 |

## 二、数据库连接类

| 报错关键词 | 原因 | 解法 |
| --- | --- | --- |
| `factoryBeanObjectType` | MP 用了 Boot2 的 starter | 换 `mybatis-plus-spring-boot3-starter` |
| `Public Key Retrieval is not allowed` | MySQL 8 认证机制 | url 加 `allowPublicKeyRetrieval=true` |
| `Access denied for user` | 密码/端口不对 | 核对 yml 与 compose 的 `MYSQL_ROOT_PASSWORD` |
| `Table 'shiyi.user' doesn't exist` | init.sql 没跑成 | 进容器 `show tables;` 检查，必要时手动执行 |
| 时间差 8 小时 | MySQL 8 驱动没给时区 | url 加 `serverTimezone=Asia/Shanghai` |

## 三、环境类

| 问题 | 现象 | 解法 |
| --- | --- | --- |
| Docker pull 超时 | 镜像拉不下来 | Docker Desktop 配 `registry-mirrors`；逐个 pull 单独重试 |
| ES 启动即退 | `vm.max_map_count [65530] is too low` | `wsl -d docker-desktop -u root sysctl -w vm.max_map_count=262144` 后重启 ES |
| sysctl 设置丢失 | Docker 重启后 ES 又起不来 | Windows + WSL2 无解，重跑上面命令 |
| IDEA 里 Lombok 报红但能跑 | 注解处理器没开 | Settings → Build → Compiler → Annotation Processors → Enable |

## 四、通用排错心法

- **先读堆栈里的版本号**，兼容性问题一眼破案（见 [Boot4 降级复盘](./sy_9)）
- **看日志尾部**：`docker compose logs --tail 20 <服务名>`，启动失败的原因永远在最后几十行
- **一次只改一处**再验证，连环报错时尤其实用——这次两连错，每修一个要重新构建确认
- 报错信息会撒谎：`sqlSessionFactory is required` 看着像少配置，实际是版本代差

## 小结

- "不报错的错误"（分页失效、缓存穿透）比崩溃更危险，靠**知道它存在**来防
- 预期内异常单独 handler + 压低日志级别，是日志素养的基本功
- 排错先版本、再日志、再配置，顺序别反
