# 工程骨架与包结构

> 第 1 课的前置内容（补录）：怎么创建工程、每个依赖为什么加、包为什么这么分。三件套本体见 [统一响应](./sy_3)、[业务异常](./sy_4)、[全局异常处理器](./sy_5)。

## 创建工程

[start.spring.io](https://start.spring.io) 生成：Group `com.shiyi`、Artifact `shiyi-server`、Java 17、依赖选 Spring Web。

::: warning 版本核对
initializr 的 Boot 版本默认跟着最新走（现在是 4.x），**生成后先看一眼 pom 的 parent 大版本**，和生态件（MP/Sa-Token 的 starter）对齐再写代码——本项目就栽过这跟头，见 [Boot4 降级复盘](./sy_9)。
:::

## 为什么 JDK 17 + Boot 3

Spring Boot 3.x 强制最低 JDK 17。简历上写 Boot 2.x + JDK 8，面试官第一反应"培训班老项目"——这是第一个必被问的问题，答案就一句：3.x 是当前生产主流线，新特性和生态适配都在这边。

## 三个依赖，各管一件事

| 依赖 | 作用 | 备注 |
| --- | --- | --- |
| spring-boot-starter-web | Web MVC + 内嵌 Tomcat | |
| spring-boot-starter-validation | 参数校验（@NotBlank/@Size/@Valid） | 第 3 课的 DTO 校验全靠它，第 1 课先装好 |
| lombok | 编译期生成 getter/setter/构造器 | IDEA 需开 Annotation Processors |

版本都不用写——由父 pom 的 `spring-boot-dependencies` BOM 统一管理。面试问"依赖版本冲突怎么处理"，标准答案之一就是"尽量走 starter 的 BOM 管版本"。

## 包结构：按业务，不按技术

```
com.shiyi
├── common      # 三件套、常量、工具
├── config      # Redis/MQ/ES/Sa-Token 等配置类
├── infra       # MinIO、地图 API 等三方封装
└── module
    ├── auth    # controller / service / dto / vo / mapper
    ├── user
    ├── course
    ├── order
    └── seckill
```

关键选择：`module` 下**按业务域分包**，每个域里再分 controller/service/mapper；而不是全项目一个大平层的 controller/service/mapper。

**为什么（面试原话级答案）**：业务边界清晰，加功能只动一个域的包；将来真要拆微服务，一个包整体搬走即可——"模块化设计保留了拆分能力"。按技术分包则是所有 controller 堆一起，业务边界全靠注释。

## 最小可跑配置

```yaml
server:
  port: 8080

spring:
  application:
    name: shiyi-server
```

验证方式：写个 `/api/v1/auth/ping` 返回 `Result.ok("pong")`，再写个 `/err` 主动抛 `BusinessException`——确认"业务代码随手 throw → 全局处理器接住 → 前端拿到统一 JSON"这条链路通了。**以后所有接口都建在这条链路上。**

## 小结

- 生成工程先核对 Boot 大版本，再接生态件
- validation 第 1 天就装，校验注解从 DTO 开始用
- 按业务分包是给"以后可能拆"留的路，也是能讲出口的设计理由
