# 事务与传承人入驻

> 第一个多表写操作：入驻 = 建 inheritor 档案 + 升级 user 角色。借这个场景讲透 @Transactional。

## 业务规则

- 用户申请入驻 → 创建 inheritor 记录（`verify_status=0` 待审核）+ user.role 升级为 INHERITOR
- **角色先给、认证后补**：能发课（课要过审），认证结果不影响发课资格
- 一个用户只能有一条档案：数据库 `uk_user_id` 唯一索引 + 代码查重双层防护

## 核心代码

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void apply(InheritorApplyDTO dto) {
    Long userId = StpUtil.getLoginIdAsLong();
    Long exists = inheritorMapper.selectCount(
            new LambdaQueryWrapper<Inheritor>().eq(Inheritor::getUserId, userId));
    if (exists > 0) {
        throw new BusinessException("你已提交过入驻申请");
    }
    Inheritor inheritor = new Inheritor();
    inheritor.setUserId(userId);
    inheritor.setName(dto.getName());
    inheritor.setHeritageItemId(dto.getHeritageItemId());
    inheritor.setBio(dto.getBio());
    inheritor.setContact(dto.getContact());
    inheritor.setVerifyStatus(Inheritor.VERIFY_PENDING);
    inheritorMapper.insert(inheritor);

    // 角色升级：精确改一个字段
    userMapper.update(null, new LambdaUpdateWrapper<User>()
            .eq(User::getId, userId)
            .set(User::getRole, "INHERITOR"));
}
```

## @Transactional 三讲（面试高频）

1. **原理一句话**：Spring 用 AOP 包住方法——进入时开启事务（绑定同一个数据库连接），正常返回提交，抛异常回滚。方法内两次写操作要么都成功要么都失败，不会出现"档案建了、角色没升"的半截状态
2. **默认只回滚 RuntimeException**。`rollbackFor = Exception.class` 让受检异常也回滚——工程习惯，无脑带上不吃亏
3. **自调用失效**：同一个类里方法 A 直接调方法 B（`this.apply()`），B 的事务注解**不生效**——事务是代理对象加的，`this` 绕过了代理。"事务失效场景"面试题的第一名，今天写的是 controller→service 跨类调用，走代理，没事

::: warning 自调用失效
事务方法必须从外部 Bean 调用才走代理。同类内部 `this.xxx()` 调用事务方法 = 裸奔。
:::

## 只改一个字段：LambdaUpdateWrapper

改角色没用"查出来 → updateById 回写"，因为那样 UPDATE 语句带着全部字段走。只动一个字段用 `set()` 精确打击，减小锁范围：

```java
userMapper.update(null, new LambdaUpdateWrapper<User>()
        .eq(User::getId, userId)
        .set(User::getRole, "INHERITOR"));
```

`update(null, wrapper)` 第一个参数传 null，表示所有 SET 都来自 wrapper。

## 鉴权的"鸡生蛋"问题

`/inheritor/apply` 上**不能**挂 `@SaCheckRole("INHERITOR")`——用户正是因为还不是传承人才来申请，类级一锁谁都进不来了。

::: tip
鉴权注解要**一个方法一个方法**想清楚"谁能调"，不能图省事整类一挂。同控制器里 `/me` 才挂 INHERITOR。
:::

## 常量消灭魔法数字

状态值常量定义在实体类顶部，业务代码只写常量名：

```java
public static final int VERIFY_PENDING = 0;
public static final int VERIFY_PASSED = 1;
public static final int VERIFY_REJECTED = 2;
```

`setVerifyStatus(Inheritor.VERIFY_PASSED)` 谁都看得懂；裸写 `setStatus(1)` 三个月后自己都得翻注释。

## 小结

- 多表写操作必须 `@Transactional(rollbackFor = Exception.class)`，放 service 层
- 事务失效第一名是自调用，记住"this 绕过代理"
- 精确更新用 UpdateWrapper 的 set()，别整实体回写
- 鉴权注解按方法粒度设计，小心鸡生蛋
